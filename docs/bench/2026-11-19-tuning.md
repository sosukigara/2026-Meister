# 2026-11-19 パラメータ調整（PR3）

ベースライン（`2026-11-18-baseline.md`）で見えた 2 つの問題に対して、
原因が説明できる変更だけを入れて 30 run で測り直した。
**両者は同一バイナリ・同一ゴール・同一ワールドで取得している。**

## 変更内容

| パラメータ | 変更前 | 変更後 | 根拠 |
|---|---|---|---|
| `xy_goal_tolerance` / `yaw_goal_tolerance` | 0.25 / 0.25 | **0.15 / 0.15** | 最終誤差 0.298 m が許容を超えていた。判定を締めて実際に寄せる |
| `lookahead_dist` / min / max | 0.6 / 0.3 / 0.9 | **0.45 / 0.25 / 0.8** | 経路長比 0.82 はショートカット。先読みを短くして経路に沿わせる |
| `cost_scaling_factor`（global/local） | 3.0 | **2.0** | 高コスト帯を広げ、障害物から離れた経路を選ばせる |

変更ファイル: `ros/src/ros2_autonomous_nav/config/mapping_nav_params.yaml`

## 判断

**採用する。** 最終誤差が許容内に入り、経路追従も改善した。
遅延と CPU 増は許容範囲（6.9 秒／0.52 コア、目標 0.60 未満）。

## 未解決: 最小クリアランス 57 mm

`cost_scaling_factor` を下げても変化しなかった（0.060 → 0.058）。
さらに **初期姿勢を除いた「走行中」の値でも同じ**だったため、
スポーン地点ではなく**走行経路そのもの**が原因である。

調査の結果、低い値を出しているのは **ゴール 0 (0.02, -2.32) のみ**で、
他の 9 ゴールは 0.36 m 以上ある。したがって特定の狭い区間を通る経路が原因で、
パラメータ全体の傾向ではない。

次の手がかり（未検証）:

- ゴール選定の `--min-clearance`（既定 0.5 m）は**ゴール地点**しか見ていない。
  経路全体の余裕は保証していない。
- SmacPlanner2D の `cost_penalty` / `reverse_penalty` を上げれば、
  高コスト帯を避ける経路が選ばれる可能性がある。
- それでも改善しない場合、その区間は物理的に 6 cm しか余裕がない可能性がある。
  そのときは「パラメータの問題」ではなく「コース設定の問題」として扱う。
